Meridian — Trust-Aware Confluence AI Agent

An enterprise RAG and MCP agent that finds authoritative documentation, detects conflicting instructions, and generates grounded answers with live citations.

Meridian combines semantic retrieval with explicit documentation governance. It synchronizes governed pages from Confluence Cloud, generates embeddings with Amazon Titan, stores them in PostgreSQL with pgvector, and produces grounded answers using Llama 3.3 through AWS Bedrock. A custom MCP server exposes knowledge-search, grounded-answer, page-reading, and conflict-detection tools to the agent.

Why it matters

The problem

Enterprise Confluence spaces often contain duplicate procedures, old guides, draft documentation, FAQs, audit reports, and inconsistent terminology. Traditional keyword search returns several pages, while basic vector search ranks documents by semantic similarity without determining whether those documents are authoritative. That creates a serious problem: the most relevant-looking page may contain outdated instructions.

The solution

I built Meridian, a trust-aware Confluence AI agent that separates relevance from authority. The agent retrieves semantically related documentation, then applies an explainable governance policy based on document status, authority, type, freshness, and supersession relationships. Canonical procedures are promoted, while stale, draft, under-review, and superseded pages remain visible as clearly identified warnings. The final answer is generated only from the recommended evidence and includes citations to the original Confluence pages.

System design

Architecture

The ingestion pipeline synchronizes pages from Confluence Cloud, maps governance labels into retrieval metadata, creates heading-aware chunks, generates Titan embeddings, and stores the results in PostgreSQL with pgvector. At query time, the React interface calls FastAPI, which drives a Bedrock tool-calling agent against a custom MCP server. The trust-aware RAG pipeline reranks retrieved evidence and splits it into recommended and conflicting branches before Llama 3.3 generates a grounded, cited answer.

Design principle

Relevance is not the same as trust

For one access question, a superseded Confluence guide received a raw semantic score of 0.7594, while the canonical procedure received only 0.5691. A basic vector-search system would likely recommend the outdated guide.

Meridian applied its governance policy and raised the canonical procedure to a final score of 0.8191, while reducing the superseded guide to 0.5194 and displaying it as a warning.

How it was built

Engineering decisions

Governance metadata as a first-class signal

Status, authority, document type, freshness, and supersession relationships are modeled explicitly, so ranking decisions are explainable rather than a black box similarity score.

Heading-aware chunking

Chunks are split along Markdown heading boundaries with controlled overlap, preserving page title and section path for stable, human-readable citations.

Low-confidence rejection before generation

A raw semantic-similarity gate (0.30) runs before any Bedrock call. Below the threshold, the agent returns an insufficient-evidence result instead of guessing, avoiding unnecessary generation cost.

Content fingerprinting for incremental refresh

Each chunk is fingerprinted so unchanged content is never re-embedded. A no-change refresh across all 14 live chunks skipped every embedding call.

Shared knowledge service across REST and MCP

FastAPI and the custom MCP server both call the same underlying knowledge service, so retrieval, reranking, and generation logic is implemented once.

Bounded, observable agent loop

The tool-calling agent enforces step and token limits and de-duplicates repeated tool calls, with every step, score, and timing surfaced back to the UI.

Operations

Security and production deployment

The portfolio environment runs locally in Docker so it doesn't leave cloud infrastructure idling between demos. The container topology mirrors a production-shaped deployment target:

Local portfolio environment

  • Dockerized FastAPI backend
  • Dockerized PostgreSQL with pgvector
  • Local MCP server over stdio
  • No idle cloud spend between demos

Production target

  • ECS Fargate for the API and agent
  • RDS PostgreSQL with pgvector
  • IAM task roles for least-privilege Bedrock access
  • Secrets Manager for credentials
  • HTTPS at the load balancer
  • CloudWatch for logs and metrics

Full implementation, architecture docs, evaluation corpus, Docker configuration, and automated tests are on GitHub.
